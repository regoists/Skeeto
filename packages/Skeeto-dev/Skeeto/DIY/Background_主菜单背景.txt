# Skeeto Background Engine 素材包制作规范

支持松散文件和 VPK 素材，但是通常更建议直接使用松散目录。MP4 目前以 H.264 视频轨作为可确保的支持范围；实际能否解码音轨还取决于 Windows Media Foundation 中是否存在对应音频解码器。
由于求生的限制，对MP4格式的兼容实际上是要在后台实时编解码，播放效果肯定赶不上视频播放器里的效果，但是目前的效果我认为是不错的，图省事懒得做bik的可以直接使用。对流畅度要求比较高的玩家，也可继续使用bik格式。skt对bik格式也增加了一定的拓展。
虽然skt支持4k视频，但是不是很建议使用，4k视频后台解码压力比较大，播放速度很可能跟不上。

​PS：如果发现自己导入素材后，播放速度变慢或者卡顿，说明你目前的素材分辨率太高了。skeeto background engine并不是真的把一个mp4视频播放器做进了求生里，对于mp4格式，是需要在后台实时解码的，不是提前把整个视频一次性读进内存。 4k视频的计算量太大了，以相同帧率、编码格式和画面复杂度估算，假如说1080p视频的计算量为100%，那么2k视频就是178%，4k视频将达到惊人的400%。
因此除非你对自己的cpu和gpu性能都非常自信，否则不建议使用4k视频，4k图片是没问题的。我自己的台式是r5 9600x+rtx 5070，实测4k视频播放还是明显拖慢。进地图之后打开skt菜单可以看到上一次主菜单视频播放的速度和缓存情况。
对于4k视频skt确实支持，skeeto会尝试使用硬件解码，并将高分辨率视频缩放到适合游戏显示的尺寸，但原始4K视频仍然需要先完成解码，因此不能消除其额外压力。 为保证播放流畅和游戏性能，建议优先使用1080p素材，配置较高时可以尝试2k，通常不建议使用4k mp4。相比提高视频分辨率，合理的码率和帧率通常更重要。 

相关控制台指令：
控制台 skeeto_background_next：立即切换到下一个背景。
控制台 skeeto_background_reload：重新扫描背景文件。
控制台 skeeto_background_toggle：开关 Background Engine。
控制台 skeeto_background_volume <0-100> 设置背景视频音量，仅支持修改mp4格式，暂不支持对单个视频单独调节音量。


## 1. 最简单的做法（推荐）

松散素材可以直接放在以下任意一个目录，推荐使用第一种：(没有对应的文件夹就直接新建)

```text
Left 4 Dead 2/left4dead2/skeeto/backgrounds/rain.mp4
Left 4 Dead 2/left4dead2/skeeto/backgrounds/city.bik
Left 4 Dead 2/left4dead2/skeeto/backgrounds/night.jpg

Left 4 Dead 2/skeeto/backgrounds/rain.mp4
```

第二种游戏根目录写法作为兼容路径保留。素材只扫描 `backgrounds` 这一层，不递归扫描里面的子文件夹。添加文件后，在主菜单执行 `skeeto_background_reload` 即可重新扫描，不必重启游戏。

文件名去掉扩展名后，同时作为背景 ID 和菜单显示名。

支持 `.png`、`.jpg`、`.jpeg`、H.264 `.mp4` 和 `.bik`，扩展名不区分大小写。

文件名去掉扩展名后的部分必须在 63 字节以内。英文字母和数字通常各占 1 字节，中文在 UTF-8 中通常各占 3 字节。现在允许空格、`-`、`_`、圆括号、方括号等普通文件名字符；禁止 `/`、`\`、`=`、`;` 和控制字符。为兼容 Windows、本地代码页、VPK 工具和其他玩家的系统环境，发布素材包时仍建议优先使用英文、数字、空格、`-` 和 `_`。

背景 ID 不区分大小写。同一个 ID 不要同时放多种格式，例如 `rain.mp4`、`Rain.bik` 会被视为重名，只保留扫描顺序靠前的一项。文件名开头和结尾不要使用空格；Windows 本身也可能自动处理结尾的空格或句点。

所有视频固定循环；MP4 音量和画面显示方式统一在 Skeeto 菜单中设置。

## 2. VPK 打包   此方法有一定的弊端和局限，通常不建议使用。skt增加对这种方法的兼容主要是方便mod的分发和使用。

VPK 内路径必须从 `skeeto/backgrounds/` 开始，而不是放进原版 `media/`：

```text
my_background.vpk
└─ skeeto
   └─ backgrounds
      ├─ rain.mp4
      └─ city.bik
```

玩家只需像普通 Mod 一样安装 VPK；不需要覆盖 `left4dead2/media/l4d2_background01~05.bik`，当启用SBE的功能时，这个原版bik目录不会被读取

## 3. MP4 与 BIK 的实现差异

- MP4：由 Windows Media Foundation 解码，按媒体时间戳送显，再上传到持久 D3D9 双纹理。音轨由独立的 Media Foundation 读取器解码成 PCM 后交给 Windows 系统混音器，和首个视频送显时刻一起启动。普通来源使用 12 帧队列；高于 1080p 的来源使用 16 帧队列，并在首次播放时最多等待 500 ms 尽量积累 12 帧。进入地图后停止解码、绘制和声音。
- BIK：交给游戏自己的 `VBik001` 播放器和视频材质，不经过 MP4 的 RGB32 逐帧上传路径。每个选中背景创建独立材质，因此不依赖原版 5 个背景槽。
- VPK 内 BIK：L4D2 的原生 Bink 路径会排除封包文件，Skeeto 因此首次把它分段提取到 `%LOCALAPPDATA%\Skeeto\background_cache\`，之后直接复用缓存并交给原生播放器。提取每次 Paint 最多处理 1 MiB，避免一次性申请几百 MiB 内存或长时间阻塞一帧；当前单文件安全上限为 1 GiB。

### 为什么会使用 `%LOCALAPPDATA%`

`%LOCALAPPDATA%` 是当前 Windows 用户的本地应用数据目录，通常位于：

```text
C:\Users\你的用户名\AppData\Local\Skeeto\background_cache\
```

松散 MP4 和松散 BIK 会直接读取原文件（所谓的松散指的是你直接放在你游戏根目录里了），不会复制到这里。图片也不会写入这里。只有 VPK 内的视频需要缓存：Windows Media Foundation 和 L4D2 的 Bink 播放器都更适合接收真实磁盘文件路径，不能直接把 VPK 内部路径当普通视频文件打开，因此 Skeeto 首次选中该视频时把压缩视频原文件写入缓存，后续直接复用。

缓存保存的是原始 `.mp4` 或 `.bik` 文件，不是逐帧解码后的巨大图片序列。因此磁盘占用大致等于实际播放过的 VPK 视频文件大小，不会按“分辨率 × 总帧数”膨胀。不过当前不会自动清理已经不再使用的旧缓存；如果经常更换很多大型 VPK 视频，C 盘占用会逐渐增加。可以在游戏完全退出后手动删除整个 `background_cache` 文件夹，下一次播放 VPK 视频时会重新生成。VPK 内 MP4 的单文件上限为 256 MiB，VPK 内 BIK 的单文件上限为 1 GiB；松散 MP4 不受 256 MiB 限制。

### MP4 当前局限

- 正式保证范围是 H.264 MP4；H.265/HEVC、AV1、VP9 或特殊封装不保证可用。
- 音频能否播放取决于 Windows Media Foundation 是否支持素材中的音频编码；AAC 通常最稳妥。
- 最大解码尺寸为 3840×2160。松散 MP4 没有 256 MiB 上限；VPK 内 MP4 因当前需要整文件读入内存再写入媒体缓存，保留 256 MiB 安全上限。高码率、4K 或解码压力很大的视频可能增加 CPU、内存、显存带宽和首次缓冲时间。
- MP4 需要在后台解码成画面帧并上传至 D3D9 纹理，无法像游戏原生 BIK 那样完全走 Source 自带的视频链路。帧率不稳定、时间戳异常或编码结构复杂的文件可能出现短暂停顿。
- 进入地图后会停止解码、绘制和声音；该功能只服务于主菜单背景。

### BIK 当前局限

- BIK 依赖当前游戏提供的 `VBik001` 接口和 Bink 解码能力；由其他新版 Bink 工具制作、编码特性不兼容的文件可能无法打开。
- VPK 内 BIK 首次播放需要先提取到本地缓存，文件越大等待越久；松散 BIK 没有这一步。
- VPK 内 BIK 单文件上限为 1 GiB。BIK 会播放素材自身携带的音轨；当前 `VBik001` 没有经过验证的单实例音量接口，因此菜单中的 MP4 音量只控制 MP4，不控制 BIK。BIK 的实际音量由素材本身及游戏原生 Bink 音频链路决定。
- Skeeto 为每个选中素材创建自己的视频材质，不受原版五个主菜单 BIK 槽位限制，但总背景登记数量仍限制为 256 个。

Background Engine 最多登记 256 个背景，这是防止异常素材包导致无界扫描的安全上限，不是原版的 5 个 BIK 槽限制。

## 4. 每次启动随机选择

菜单打开该选项后，每个游戏进程只在完整扫描 loose 文件与 GAME/VPK 资源后随机一次，候选池包含 PNG、JPG/JPEG、MP4 和 BIK。

- 返回主菜单或重新扫描不会再次随机。
- 手动切换背景只改变本次运行中的选择，不会自动关闭随机选项。
- 下次启动游戏会重新从完整候选池随机。

## 5. 失败回退

素材缺失、文件过大、解码失败、BIK 接口或绘制接口不可用时，只放弃当前自定义背景并保留原版主菜单 BIK，不覆盖或删除原版文件。
